Token Optimizer

AMD Developer Hackathon: ACT 2Jul 2026

A hybrid routing agent that cuts LLM inference cost and latency by sending each query to the cheapest capable option: a local model, a deterministic solver, or the cloud.

Overview

Built for the AMD Developer Hackathon: ACT 2, Token Optimizer addresses a simple problem: most LLM queries don't need a frontier model, but routing everything to one anyway wastes cost and latency. The agent inspects each incoming query and routes it to the cheapest option that can actually handle it.

Simple, deterministic tasks are solved directly in Python with no model call at all. Moderate queries go to a local Ollama model (qwen2.5:3b) running on-device with zero API cost. Only queries that genuinely need frontier-level reasoning escalate to the Fireworks API, keeping average cost and latency down without sacrificing capability on the queries that need it.

Engineering Decisions

  • Local-first with qwen2.5:3b via Ollama. Runs a small model on-device for the bulk of moderate-complexity queries, avoiding API cost and network latency for anything that doesn't need it.
  • Deterministic solvers before any model call. Queries with a clear rule-based answer skip inference entirely, which is both faster and free.
  • Fireworks API as the escalation tier. Reserved for queries the local model and solvers can't confidently handle, so inference cost scales with actual query difficulty rather than a flat per-query rate.
  • Containerized and shipped through CI. Docker plus a GitHub Actions pipeline to GHCR made the routing agent reproducible and easy to deploy for judging.
